# CLAUDE.md — написание кода 1С с опорой на базу знаний 1confdb-knw

Этот репозиторий содержит экстрактор конфигураций 1С:Предприятие 8 в SQLite и
MCP-сервер **1confdb-knw** — read-only базу знаний по конкретной конфигурации:
объекты метаданных, реквизиты с типами, табличные части, модули кода (BSL),
запросы СКД. Сервер НЕ изменяет конфигурацию — он справочный; код и запросы ты
пишешь сам, а из базы берёшь факты: имена объектов, полей, методы-примеры.

Инструкции протокола (`initialize.instructions`) уже содержат полный справочник
по схеме БД и глоссарий; этот файл задаёт рабочий процесс и стиль кода.

## Подключение к серверу

- stdio: `1confdb-knw.bat <база.sqlite>` (или `python -m confdb.mcp_server <база>`);
- сеть: `1confdb-knw.bat <база> --port 8765`, клиент — `{"url": "http://127.0.0.1:8765/mcp"}`;
  с другой машины — через туннель `ssh -L 8765:127.0.0.1:8765 user@host`.

Если сервер не поднят, попроси пользователя запустить его (confdb-ui.bat, пункт 1)
или запусти сам одной из команд выше.

## Глоссарий 1С

Catalog = справочник, Document = документ, InformationRegister /
AccumulationRegister / AccountingRegister = регистры сведений / накопления /
бухгалтерии, Enum = перечисление, DataProcessor = обработка, Report = отчёт,
DefinedType = определяемый тип, CommonAttribute = общий реквизит, CommonModule =
общий модуль. Табличная часть = вложенная «таблица строк» объекта (например,
у документа строки с полями). СКД = система компоновки данных (запросы отчётов).
Все имена объектов и полей — на русском языке.

## Рабочий процесс (инструменты MCP)

1. `configuration_info` — какая конфигурация и какой релиз в базе: что за файл
   загружен (`.cf` конфигурация, `.cfe` расширение, `.epf` внешняя обработка,
   `.erf` внешний отчёт), имя, версия, режим совместимости (у обработок и
   отчётов его нет, расширение наследует режим основной конфигурации),
   исходный файл и дата выгрузки. Первый шаг, когда баз несколько или нужно
   понять, для какой версии писать код.
2. `find_objects` — найти объект по подстроке имени/пути (первый шаг всегда).
3. `object_card` — «паспорт»: реквизиты с типами, табличные части с полями,
   модули, формы и команды, ссылки вперёд/назад. У регистров измерения, ресурсы
   и реквизиты идут отдельными группами + периодичность и режим записи: прежде
   чем писать `СрезПоследних` или соединение с регистром, убедись, что нужное
   поле — измерение (только измерения дают одну строку на ключ).
4. `object_tree` — дерево объектов «как в конфигураторе» (формы, команды).
5. `find_field` — обратный поиск: у каких объектов есть поле с именем.
6. `refs_of` — связи по типам реквизитов (impact analysis: кто ссылается).
7. `module_outline` — оглавление модуля: сигнатуры, комментарии, `#Если…` БЕЗ тел.
8. `find_methods` → `find_method_context` → `get_method` — найти и
   ПЕРЕИСПОЛЬЗОВАТЬ существующий код (не изобретай процедуру, если в
   конфигурации уже есть нужная). `find_methods` ищет по имени/сигнатуре
   (`mask`) и по текстам тел методов (`text`): `text` отвечает на вопрос «где
   в коде это вообще упоминается» — все точки записи регистра, все вызовы
   общего модуля, все обращения к реквизиту, с номером строки модуля у каждого
   совпадения. Уходить для этого в полнотекстовый `sql` не нужно.
   `find_method_context` дешевле `get_method`
   на больших методах: показывает окно строк вокруг нужного вызова с номерами
   строк модуля и маркеры точки вставки (предыдущий и следующий оператор).
9. `skd_of` / `find_skd` — реальные запросы ЭТОЙ конфигурации к тем же таблицам:
   лучшие примеры именований и соединений.
10. `check_query` — ОБЯЗАТЕЛЬНАЯ проверка каждого твоего запроса перед использованием.
11. `method_dependencies` — что нужно методу для работы: общие модули и их
    экспортные методы, объекты метаданных, таблицы и поля его запросов,
    параметры. Обязателен перед переносом доработки в другую конфигурацию.
    Когда рядом открыта основная конфигурация (`db_open`), зависимости
    расширения или внешней обработки находятся в ней, а ответ называет базу,
    в которой они есть, — «объект не найден» означает, что его нет ни там,
    ни там. Запросы при этом проверяются по метаданным своей базы: для чужих
    таблиц повтори `check_query` с `db=<алиас>`.
12. `method_result_schema` — из чего состоит таблица значений/структура,
    которую возвращает штатная функция (эвристика по тексту; ответ честно
    говорит, чего он не видит).
13. `compare_object(path, db_left, db_right)` — различия одного объекта в двух
    базах: реквизиты и типы, табличные части, группы полей регистра, формы,
    модули, методы, запросы СКД. Типовая против доработанной, релиз против релиза.
14. `extension_diff(extension_db, base_db)` — что делает расширение: новые
    объекты (с префиксом расширения), заимствованные, его методы и какой штатный
    метод они замещают (`&Вместо`) или обходят (`&После`/`&Перед`), добавленные
    реквизиты, внешние зависимости.
15. `sql` — только SELECT, для всего, что не покрыто инструментами выше.

Синтаксис текстов модулей этот сервер не проверяет — для этого есть вариант
`1confdb-knw-lsp` с BSL Language Server. Ошибки инструментов возвращаются с кодом
категории (`BAD_ARGS`, `BAD_REQUEST`, `DB_LOCKED`, `DB_SCHEMA`, `DB_ERROR`,
`IO_ERROR`, `INTERNAL`); `DB_LOCKED` транзитна — вызов можно повторить.

## Типы данных в базе знаний

- `meta_attribute.type_str`: `Строка(50)`, `Число`, `Дата`, `Булево`,
  `Ссылка: Catalog/Валюты` (конкретный тип), `ОпределяемыйТип: DefinedType/Х (…)`,
  составные — члены через ` | `; голая `Ссылка` — абстрактная (любой ссылочный тип).
- `meta_attribute.tabular` — имя табличной части, если поле belongs to строкам.
- `attribute_ref` — связи реквизита с объектами: использовать для join'ов вместо
  разбора строк `type_str`.

## Язык 1С (BSL) — минимум для генерации кода

Ключевые слова русские. Каркас:

```bsl
// директивы контекста (важно: клиент и сервер — разные среды выполнения)
&НаСервере
Функция МояФункция(Параметр) Экспорт
    Перем Локальная;
    Если Условие Тогда
        // …
    ИначеЕсли Другое Тогда
        // …
    Иначе
        // …
    КонецЕсли;
    Для Каждого Строка Из Коллекция Цикл
        // …
    КонецЦикла;
    Возврат Значение;
КонецФункции

&НаКлиенте
Процедура КомандаНаКлиенте(Команда)
    // …
КонецПроцедуры
```

- Литералы: `"строка"`, `123.45`, `'20260101'` (дата), `Истина` / `Ложь`, `NULL`,
  `Неопределено`. Операторы: `=`, `<>`, `<`, `>`, `<=`, `>=`, `+ - * /`, `%`,
  `И`, `ИЛИ`, `НЕ`, скобки. Строки соединяются `+`.
- Обращение к данным: `Объект.Реквизит` (в модуле объекта),
  `Справочники.Имя`, `Документы.Имя`, `РегистрыСведений.Имя`,
  `РегистрыНакопления.Имя` — менеджеры; `Объект.Ссылка` — ссылка записи;
  табличная часть: `Объект.ИмяЧасти.Добавить()`, обход `Для Каждых Строк Из Объект.ИмяЧасти`.
- Модули в базе знаний: `code_name` = `obj` (модуль объекта), `mgr` (модуль
  менеджера), модули форм и общих модулей; у общих модулей `context`
  (Сервер / Клиент / Вызов сервера …) — учитывай контекст при заимствовании кода.
- Синонимы и имена бери ТОЛЬКО из `object_card` / `find_field` — не выдумывай.

## Язык запросов 1С — минимум

```
ВЫБРАТЬ
    Т.Ссылка,
    Т.Запасы.Номенклатура.Наименование КАК Номенклатура,
    СУММА(Т.Сумма) КАК Сумма
ИЗ
    Документ.ЗаказПокупателя КАК Т
ГДЕ
    Т.Дата >= &ДатаНачала
    И Т.Проведен
СГРУППИРОВАТЬ ПО
    Т.Ссылка,
    Т.Запасы.Номенклатура.Наименование
```

- Имена таблиц: `Справочник.Имя`, `Документ.Имя`, `РегистрСведений.Имя`,
  `РегистрНакопления.Имя` + виртуальные таблицы: `.Остатки`, `.Обороты`,
  `.СрезПоследних`, `.ОстаткиИОбороты(…)`; поля табличной части — `Т.Часть.Поле`.
- Конструкции: `ПОМЕСТИТЬ` / `УНИЧТОЖИТЬ`, `ОБЪЕДИНИТЬ [ВСЕ]`, `СОЕДИНЕНИЕ … ПО`
  (ЛЕВОЕ/ВНУТРЕННЕЕ), вложенные запросы, `ВЫБОР … КОГДА … ТОГДА … ИНАЧЕ … КОНЕЦ`,
  `ВЫРАЗИТЬ(… КАК …)`, параметры `&Имя`, необязательные области СКД `{ … }`,
  группировка — `СГРУППИРОВАТЬ ПО` (формы «СГРУППИРОВАНО» в языке запросов 1С НЕТ),
  в т.ч. `СГРУППИРОВАТЬ ПО ГРУППИРУЮЩИМ НАБОРАМ ((…), (…))`;
  `В ИЕРАРХИИ (…)`; `УПОРЯДОЧИТЬ ПО … ИЕРАРХИЯ [УБЫВ]`; `АВТОУПОРЯДОЧИВАНИЕ`;
  `ИТОГИ [поля] ПО [ОБЩИЕ] <точки>` с `[ТОЛЬКО] ИЕРАРХИЯ` и `ПЕРИОДАМИ(ГОД, …)`;
  псевдонимы полей и источников — с `КАК` или без него.
- Разыменование ссылок точками работает только по конкретным типам реквизита
  (см. `type_str`); для составных типов соединяйся через известные цели
  (`attribute_ref` / `refs_of`).
- Написал запрос → прогнал `check_query` → только потом отдавай пользователю.

## Правила

- Пути объектов инструменты отдают и принимают «как в конфигураторе»:
  `Справочник.Имя`, `Документ.Имя`, вложенные — `Справочник.Имя.ФормаЭлемента`;
  эти же точечные имена — таблицы в языке запросов. Старый формат `Catalog/…`
  понимается на вход, но наружу не возвращается.
- Общие модули в коде 1С вызываются БЕЗ префикса: `ИмяМодуля.Функция(...)`.
  Префиксы `ОбщийМодуль.`, `Общий модуль.`, `ОбщМодуль.` — ошибка, не пиши их
  (точечная форма «Общий модуль.Имя» существует только как идентификатор объекта
  в базе знаний).
- Файл базы данных — внутренность сервера: не ищи его на диске, не открывай,
  не спрашивай у пользователя путь. Все данные — только через инструменты MCP;
  произвольный SELECT — инструмент `sql`.
- Имена объектов/полей/методов — только из базы знаний, строго как в ней.
- Сначала ищи готовый код (`find_methods`, `skd_of`) — переиспользуй стиль и логику
  ЭТОЙ конфигурации, а не пиши «в вакууме».
- Учитывай директивы `&НаКлиенте` / `&НаСервере`: клиентский код не может читать
  базу напрямую, серверный — не работает с формами.
- Сервер read-only: никаких изменений через MCP; результат — текст кода/запроса
  в ответе пользователю.
