# CLAUDE.md — написание кода 1С с опорой на базу знаний 1confdb-knw

Этот репозиторий содержит экстрактор конфигураций 1С:Предприятие 8 в SQLite и
MCP-сервер **1confdb-knw** — read-only базу знаний по конкретной конфигурации:
объекты метаданных, реквизиты с типами, табличные части, модули кода (BSL),
запросы СКД. Сервер НЕ изменяет конфигурацию — он справочный: код и запросы ты
пишешь сам, а из базы берёшь факты (имена объектов, полей, методы-примеры).

**Глоссарий 1С, схему БД, формат путей объектов, правила вызова общих модулей,
мульти-базовость (`db`, `db='*'`, `db_open`/`db_use`), группы конфигураций
(`group`, `group='*'`, `group_list`/`group_use` — несколько групп открыты
одновременно, запрос к одной группе отдельный), сравнение баз
(`compare_object`, `extension_diff`, `configuration_info`), группы измерений/ресурсов/
реквизитов регистров и рекомендованный порядок работы инструментами сервер выдаёт сам** —
в `initialize.instructions` (PRIMER), при подключении. Этот файл их не повторяет.
Здесь только то, чего в PRIMER нет: как подключить сервер, категории ошибок, минимум
языка BSL для генерации кода, полный список конструкций языка запросов и правила стиля.

## Подключение к серверу

- stdio: `1confdb-knw.bat <база.sqlite>` (или `python -m confdb.mcp_server <база>`);
- несколько групп конфигураций сразу: `1confdb-knw.bat --group УНФ=unf.db
  --group УНФ=unf_ext.db --group БП=bp.db` (повтор флага добавляет базу в ту же
  группу; активна первая группа, запрос к конкретной группе — параметр `group`);
- сеть: `1confdb-knw.bat <база> --port 8765`, клиент — `{"url": "http://127.0.0.1:8765/mcp"}`;
  с другой машины — через туннель `ssh -L 8765:127.0.0.1:8765 user@host`;
- в конфиге клиента команда обязана содержать подкоманду: `-m confdb 1confdb-knw <база>`
  (без неё процесс молча умирает с usage error в stderr, клиент остаётся без инструментов).

Если сервер не поднят, попроси пользователя запустить его (`confdb-ui.bat`, пункт 1)
или запусти сам одной из команд выше.

## База из выгрузки конфигурации в файлы (правится LLM)

База знаний может быть собрана не из `.cf`, а из каталога ВЫГРУЗКИ конфигурации
в файлы (`confdb extract <каталог-выгрузки> --db out.db` — каталог с
`ConfigDumpInfo.xml` определяется автоматически). Рабочий цикл правок:

1. отредактировал файлы выгрузки (`.bsl`, XML объектов, `Rights.xml`…);
2. `confdb update <каталог-выгрузки> --db out.db` — в базу перезагружаются
   ТОЛЬКО изменённые объекты (хэши файлов против таблицы `dump_file`; обход
   без изменений — секунды даже на 5.7 ГБ);
3. запущенный MCP-сервер останавливать НЕ нужно: база в WAL, сервер сам
   подхватывает обновление (hot reload) — следующий вызов инструмента уже
   видит новые данные. Остановка требуется только для полной пересборки
   (`extract --force`): команда сама назовёт pid живого сервера.

Проверь правку модуля до `update`: `check_syntax(text=…)`, а после обновления —
`check_syntax(path=…, semantic=True)` по базе (вызовы общих модулей, объекты
метаданных, запросы разрешаются уже по отредактированной конфигурации).

## Язык 1С (BSL) — минимум для генерации кода

Ключевые слова русские. Каркас:

```bsl
// директивы контекста (важно: клиент и сервер — разные среды выполнения)
&НаСервере
Функция МояФункция(Параметр) Экспорт
    Перем Локальная;
    Если Условие Тогда
        // …
    ИначеЕсли Другое Тогда
        // …
    Иначе
        // …
    КонецЕсли;
    Для Каждого Строка Из Коллекция Цикл
        // …
    КонецЦикла;
    Возврат Значение;
КонецФункции

&НаКлиенте
Процедура КомандаНаКлиенте(Команда)
    // …
КонецПроцедуры
```

- Литералы: `"строка"`, `123.45`, `'20260101'` (дата), `Истина` / `Ложь`, `NULL`,
  `Неопределено`. Операторы: `=`, `<>`, `<`, `>`, `<=`, `>=`, `+ - * /`, `%`,
  `И`, `ИЛИ`, `НЕ`, скобки. Строки соединяются `+`.
- Обращение к данным: `Объект.Реквизит` (в модуле объекта), `Объект.Ссылка` — ссылка
  записи; менеджеры — `Справочники.Имя`, `Документы.Имя`, `РегистрыСведений.Имя`,
  `РегистрыНакопления.Имя`; табличная часть — `Объект.ИмяЧасти.Добавить()`,
  обход `Для Каждых Строк Из Объект.ИмяЧасти`.
- Модули в базе знаний: `code_name` = `obj` (модуль объекта), `mgr` (модуль менеджера),
  модули форм и общих модулей; у общих модулей `context` (Сервер / Клиент /
  Вызов сервера …) — учитывай контекст при заимствовании кода.

## Язык запросов 1С — конструкции, которые обязан принимать `check_query`

PRIMER даёт имена таблиц, виртуальные таблицы и базовый пример. Полный список
конструкций (проверен на 375 запросах СКД реальной конфигурации):

- `ПОМЕСТИТЬ` / `УНИЧТОЖИТЬ`, `ОБЪЕДИНИТЬ [ВСЕ]`, `СОЕДИНЕНИЕ … ПО`
  (ЛЕВОЕ / ВНУТРЕННЕЕ), вложенные запросы, `ВЫБОР … КОГДА … ТОГДА … ИНАЧЕ … КОНЕЦ`,
  `ВЫРАЗИТЬ(… КАК …)`, параметры `&Имя`, необязательные области СКД `{ … }`;
- группировка — только `СГРУППИРОВАТЬ ПО` (формы «СГРУППИРОВАНО» в языке запросов 1С
  НЕТ), в т.ч. `СГРУППИРОВАТЬ ПО ГРУППИРУЮЩИМ НАБОРАМ ((…), (…))`;
- `В ИЕРАРХИИ (…)`; `УПОРЯДОЧИТЬ ПО … ИЕРАРХИЯ [УБЫВ]`; `АВТОУПОРЯДОЧИВАНИЕ`;
- `ИТОГИ [поля] ПО [ОБЩИЕ] <точки>` с `[ТОЛЬКО] ИЕРАРХИЯ` и `ПЕРИОДАМИ(ГОД, …)`;
- псевдонимы полей и источников — с `КАК` или без него;
- поля табличной части — `Т.Часть.Поле`;
- разыменование ссылок точками работает только по конкретным типам реквизита
  (`type_str`); для составных типов соединяйся через известные цели
  (`attribute_ref` / `refs_of`).

Написал запрос → прогнал `check_query` → только потом отдавай пользователю.
Написал/изменил код модуля BSL → прогнал `check_syntax(text=<код>)` → только потом отдавай.

## Ошибки инструментов

Ошибка возвращается с кодом категории: `BAD_ARGS`, `BAD_REQUEST`, `DB_LOCKED`,
`DB_SCHEMA`, `DB_ERROR`, `IO_ERROR`, `INTERNAL`. `DB_LOCKED` транзитна — вызов можно
повторить; `BAD_ARGS` читай как «не тот параметр», а не как «данных нет».

В групповом вызове (`group=<имя>`, `group='*'`, `db='*'`) ошибка одной базы — это
её секция с тем же кодом категории, а не отказ всего вызова: остальные базы
отвечают штатно, а ответ заканчивается строкой `баз с ошибкой N из M: <алиасы>`.
Это граница достоверности ответа — N баз из M не ответили, и их секции называют
причину. `isError` у такого вызова появляется только когда отказали все базы.

## Правила стиля

- Имена объектов, полей, методов и синонимы — ТОЛЬКО из базы знаний (`object_card`,
  `find_field`), строго как в ней; не выдумывай.
- Сначала ищи готовый код (`find_methods`, `skd_of`) и переиспользуй стиль и логику
  ЭТОЙ конфигурации, а не пиши «в вакууме».
- Поиск отдаёт одну страницу: `limit` (1..200) и `offset`, а последняя строка ответа
  называет общее число совпадений и `offset` следующей порции. Нужны остальные —
  листай тем же поиском, а не раздувай `limit` и не сужай маску наугад.
- Общие модули в коде вызываются БЕЗ префикса: `ИмяМодуля.Функция(...)`. Префиксы
  `ОбщийМодуль.`, `Общий модуль.`, `ОбщМодуль.` — ошибка (точечная форма
  «Общий модуль.Имя» существует только как идентификатор объекта в базе знаний).
- Учитывай директивы `&НаКлиенте` / `&НаСервере`: клиентский код не может читать базу
  напрямую, серверный — не работает с формами.
- Файл базы данных — внутренность сервера: не ищи его на диске и не спрашивай путь;
  все данные — через инструменты MCP, произвольный SELECT — инструмент `sql`.
- Сервер read-only: никаких изменений через MCP; результат — текст кода/запроса
  в ответе пользователю.
- Синтаксис кода BSL сервер **проверяет** встроенным парсером — инструмент `check_syntax`
  (без платформы и Java). Написал/правил модуль → прогнал `check_syntax(text=<код>)` →
  только потом отдавай пользователю; существующий модуль конфигурации проверяется
  `check_syntax(path, code_name)`. Это грамматика языка (блок-конструкции, препроцессор,
  строки, выражения). С `semantic=True` код дополнительно разрешается против
  ЭТОЙ конфигурации (ERROR/WARNING/INFO): вызов несуществующего или не-Экспорт метода
  общего модуля, обращение к несуществующему объекту (`Справочники.Х`), ошибки в текстах
  запросов внутри модуля (синтаксис + таблицы/поля), вызов серверного общего модуля из
  `&НаКлиенте`-метода, неиспользуемые локальные переменные, `Прервать`/`Продолжить` вне
  цикла, устаревшие и небезопасные глобальные вызовы — пиши современный код:
  `ТекущаяДатаСеанса` вместо `ТекущаяДата`, `СообщениеПользователю` вместо `Сообщить`,
  `СтрНайти` вместо глобальной `Найти`, избегай модальных `Предупреждение`/`Вопрос`,
  `Вычислить`/`Выполнить` с произвольным кодом и обращений к ФС/интернету без нужды.
  Вывод типов выражений не выполняется; имена, которые не разрешились ни во что известное
  (платформенный API, атрибуты форм), не помечаются — это граница анализа;
  для зависимостей кода есть `method_dependencies`, для запросов — `check_query`.
  Отдельный вариант `1confdb-knw-lsp` (шлюз к Java BSL Language Server) больше не нужен.
